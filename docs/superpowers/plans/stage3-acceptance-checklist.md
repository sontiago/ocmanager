# Приёмка этапа 3 на живом сервере

Повторить на чистых Debian 12 и Ubuntu 22.04 (нужны два домена с A-записями и бот).

- [ ] `git clone` + `sudo ./install.sh` доходит до зелёного `ocm status` (reconcile — после 5–6 минут); админка открывается по SSH-туннелю.
- [ ] Обрыв установки (Ctrl+C на шаге `build`) и повторный `sudo ./install.sh`: продолжается, `.env`, CA и админ не пересозданы.
- [ ] Повторный запуск уже установленного продукта ничего не ломает.
- [ ] `ocm backup`: файл `.enc` в `/var/backups/ocmanager`, права 0600/0700; `systemctl list-timers` показывает `ocm-backup.timer`.
- [ ] Восстановление на второй чистой машине (`ocm restore`): выданные ранее ключи клиентов подключаются.
- [ ] Неверный ключ при `ocm restore`: отказ, сервисы не остановлены.
- [ ] `ocm update` на тестовом коммите: копия → обновление → `ocm status`; `ocm update` с правкой в клоне — отказ без изменений.
- [ ] `ocm rollback` (с восстановлением базы и без).
- [ ] Остановить Postgres, выполнить `ocm backup`: код 1, алерт админу пришёл в Telegram (после `ocm admin-chat`).
- [ ] Состарить метку `/var/backups/ocmanager/last-ok` (>36 ч): `ocm status` красный по копиям.
- [ ] Копирование на второй сервер (`backup_remote`) работает и при недоступном сервере даёт алерт.
- [ ] Установка с ответом «нет» на резервные копии: ключа и таймера нет, `ocm status` показывает SKIP, `ocm backup` подсказывает `backup-enable`; `ocm update` просит подтверждение; `ocm backup-enable` включает копии.
