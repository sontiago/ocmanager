# Этап 3 «коробка» Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (the human chose inline execution for earlier stages) or superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** `git clone` + `sudo ./install.sh` ставит продукт целиком с диалогом; на сервере появляются `ocm backup/restore/update/rollback`, ежедневный шифрованный бэкап с алертом при сбое и русская инструкция покупателя.

**Architecture:** Логика на Python (стандартная библиотека) в `deploy/installer/`, внешний мир (команды, сеть, DNS, ввод) за тремя подменяемыми интерфейсами (`Runner`, `Net`, `Prompter`); `install.sh` и `ocm` — тонкие bash-обёртки. Установка — список шагов с файлом состояния. Бэкап — один шифрованный `tar.gz`. Два новых слова в CLI бэкенда: постановка алерта админу и добавление chat id.

**Tech Stack:** Python 3.10+ stdlib (Debian 12 / Ubuntu 22.04), bash, docker compose, openssl, systemd timer; тесты pytest (из окружения бэкенда); backend: typer, существующие notifications.

**Spec:** `docs/superpowers/specs/2026-10-23-stage3-box-design.md`

## Global Constraints

- Только Debian 12+/Ubuntu 22.04+, root, Python 3.10+ и стандартная библиотека на сервере: никаких `pip install`.
- Секреты не печатаются в вывод и лог; `.env` и файл ключа бэкапов — права 0600; пароль админа передаётся CLI через stdin, не аргументом.
- Бэкап с CA никогда не лежит незашифрованным (промежуточные файлы — в каталоге 0700, удаляются в `finally`).
- Установщик ничего не меняет вне каталога установки, кроме: Docker (по согласию), swap (по согласию), `/usr/local/bin/ocm`, systemd-юнитов бэкапа, `/var/backups/ocmanager`, `/root/.ocmanager-backup-key`. Firewall не трогает.
- Все пользовательские тексты мастера — русские. Имя домена: `[a-z0-9.-]`, нижний регистр, не IP.
- Пароль админа ≥ 12 символов, ≤ 72 байт (правило `ocmanager admin create`).
- Хранение бэкапов: 14 последних. Расписание: ежедневно 03:30. Устаревший бэкап для `doctor`: старше 36 часов.

## Review Focus

1. Повторный запуск установщика после обрыва на любом шаге: продолжает, не пересоздаёт секреты и не затирает `.env`, CA и админа.
2. Домен введён с `https://`, пробелами, заглавными буквами, IP вместо имени, с портом: понятный отказ или нормализация, не ошибка на шаге Caddy.
3. Токен бота неверный или Telegram недоступен: понятное сообщение, возврат к вопросу (недоступность сети — возможность продолжить без имени бота).
4. Восстановление из бэкапа с неверным ключом или повреждённого файла: отказ до остановки сервисов, ничего не затёрто.
5. Обновление, при котором `git pull` не fast-forward (локальные правки в клоне): отказ с объяснением до сборки и до остановки чего-либо.
6. Бэкап при остановленном Postgres или полном диске: ненулевой код, алерт админу, старые копии не удалены.
7. Диск почти полон / нет `python3` / нет root: понятная остановка в самом начале.

### Task 6: Команда `ocm`: обновление и откат, остальное

**Files:**
- Create: `deploy/installer/ocm.py`, `deploy/ocm`, `deploy/installer/tests/test_ocm.py`

**Interfaces:**
